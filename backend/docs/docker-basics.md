# Docker: основы (на примере Postgres для devio)

Пятая часть справочника. Цель — понять, что такое Docker и осознанно поднять в нём PostgreSQL для devio. Докеризацию самого приложения (бэка/фронта) сознательно оставляем на потом — это тема деплоя; сейчас Docker нужен как способ запускать *инфраструктуру* разработки.

---

## 1. Какую проблему решает Docker

Классика без Docker: ставишь Postgres установщиком в систему. Он прописывается в автозагрузку, живёт где-то в недрах ОС, у него глобальный конфиг, а через полгода на другом проекте нужна другая версия — и начинается «у меня локально работает, а у тебя нет».

Docker решает это **изоляцией**: приложение запускается в контейнере — упакованном окружении со всем необходимым внутри (сам Postgres, его библиотеки, его файлы). Контейнер не знает о твоей системе почти ничего, система — о нём. Отсюда суперспособности:

- **Одна команда** — и у тебя работающий Postgres любой версии, без установщиков
- **Снёс — как не было**: контейнер удаляется бесследно, система не замусоривается
- **Воспроизводимость**: у тебя, у второго разработчика (если появится) и на CI — байт-в-байт одинаковое окружение
- **Параллельность**: Postgres 17 для devio и, скажем, Postgres 15 для другого проекта работают одновременно и не знают друг о друге

Аналогия с твоим миром: Docker для окружений — это как lockfile для зависимостей. `package-lock.json` гарантирует одинаковые пакеты у всех; Docker гарантирует одинаковый *весь мир вокруг приложения* — до версии ОС-библиотек.

## 2. Три главных понятия

**Image (образ)** — неизменяемый шаблон: «замороженная» файловая система + инструкция запуска. `postgres:17` — это образ: Debian-основа, установленный Postgres 17, команда старта. Образы скачиваются из реестра Docker Hub (это npm-реестр мира Docker, и `postgres` там — official image).

**Container (контейнер)** — запущенный экземпляр образа. Из одного образа можно поднять хоть пять независимых контейнеров. Соотношение образ → контейнер примерно как класс → инстанс.

**Volume (том)** — постоянное хранилище, прикреплённое к контейнеру. Критично понять: **файловая система контейнера эфемерна** — удалил контейнер, файлы исчезли. Для базы данных это недопустимо, поэтому каталог с данными Postgres выносится в volume, который живёт независимо от контейнеров.

Тег после двоеточия (`postgres:17`) — версия образа. Правило: **всегда фиксируй мажорную версию**. Тег `postgres:latest` — мина: в какой-то момент `latest` станет указывать на 18-ю версию, и база молча не заведётся с данными от 17-й.

## 3. Установка

- **Windows / macOS:** Docker Desktop — приложение с GUI, внутри которого движок. На Windows потребует WSL2 (виртуализированный Linux; установщик сам подскажет, обычно достаточно `wsl --install` и перезагрузки)
- **Linux:** Docker Engine из репозитория

Проверка, что всё живо:

```bash
docker run hello-world
```

Команда скачает крошечный тестовый образ и запустит контейнер, который напечатает приветствие и завершится. Увидел текст — движок работает.

## 4. Как это выглядит «руками»: docker run

Прежде чем перейти к compose-файлу, один раз посмотрим на низкоуровневый способ — так понятнее, что compose потом делает за нас:

```bash
docker run -d \
  --name devio-db \
  -e POSTGRES_USER=devio \
  -e POSTGRES_PASSWORD=devio \
  -e POSTGRES_DB=devio \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql/data \
  postgres:17
```

Разбор флагов:

- `-d` (detached) — в фоне, терминал не занят
- `--name devio-db` — имя контейнера, чтобы обращаться по-человечески
- `-e КЛЮЧ=значение` — переменные окружения **внутрь контейнера**. Официальный образ Postgres читает эти три: при первом старте создаёт юзера, пароль и базу
- `-p 5432:5432` — проброс порта, читается «хост:контейнер». Контейнер изолирован, его порты снаружи не видны; этот флаг говорит: «порт 5432 моей машины → порт 5432 контейнера». Именно поэтому твой FastAPI сможет ходить на `localhost:5432`
- `-v pgdata:/var/lib/postgresql/data` — «том:путь-в-контейнере»: каталог данных Postgres живёт в томе `pgdata`, переживает пересоздание контейнера
- `postgres:17` — образ

Работает, но команда длинная, её надо где-то хранить, а с ростом проекта контейнеров станет больше. Поэтому —

## 5. Docker Compose: конфигурация как файл

Compose — способ описать те же контейнеры декларативно, в YAML-файле рядом с кодом. Тот же смысл, что `package.json scripts` против «запомни длинную команду»: конфигурация версионируется в git и запускается одинаково у всех.

```yaml
# backend/docker-compose.yml
services:
  db:
    image: postgres:17
    environment:
      POSTGRES_USER: devio
      POSTGRES_PASSWORD: devio
      POSTGRES_DB: devio
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

Соответствие с `docker run` один-в-один: `services.db` = контейнер (имя сервиса — `db`), `environment` = флаги `-e`, `ports` = `-p`, `volumes` = `-v`. Нижний блок `volumes:` объявляет сам том — Docker создаст и будет управлять им сам.

Пароль `devio` открытым текстом — для **локальной** разработки нормально: база доступна только с твоей машины. На проде пароли поедут через секреты, но это тема деплоя.

## 6. Рабочие команды

Всё выполняется из папки с `docker-compose.yml` (у нас — `backend/`):

```bash
docker compose up -d        # поднять всё описанное (скачает образ при первом запуске)
docker compose ps           # что сейчас запущено и в каком статусе
docker compose logs -f db   # логи постгреса вживую (-f = follow); Ctrl+C — выйти
docker compose down         # остановить и удалить контейнеры (тома НЕ трогаются)
docker compose down -v      # ...и удалить тома — полный сброс базы, осознанно!
```

Мысленная модель повседневной работы: **контейнеры — расходники, том — ценность.** `down` + `up -d` можно делать сколько угодно — данные в `pgdata` живы. `down -v` — «снести базу к нулю» (иногда это и нужно: начать с чистого листа и накатить миграции заново).

Пара команд для заглядывания внутрь:

```bash
docker compose exec db psql -U devio -d devio   # консоль psql прямо в контейнере
docker volume ls                                 # список томов на машине
```

`exec` запускает команду внутри работающего контейнера — так ты попадаешь в psql (интерактивную консоль Postgres) без установки чего-либо в систему. Проверь после первого запуска: `\dt` покажет таблицы (пока пусто), `\q` — выход.

## 7. Как это стыкуется с devio

Картина целиком на твоей машине:

```
┌─ твоя система ──────────────────────────────────────┐
│                                                     │
│  Next.js (localhost:3000)                           │
│      │ HTTP                                         │
│  FastAPI (localhost:8000) ← запускается как обычно, │
│      │                       БЕЗ докера             │
│      │ postgresql+asyncpg://devio:devio@localhost:5432/devio
│      ▼                                              │
│  ┌─ Docker ─────────────────────────┐               │
│  │  контейнер db (postgres:17)      │               │
│  │  порт 5432 ← проброшен наружу    │               │
│  │  данные → том pgdata             │               │
│  └──────────────────────────────────┘               │
└─────────────────────────────────────────────────────┘
```

Обрати внимание: `localhost:5432` в `DATABASE_URL` работает благодаря пробросу `ports`. Хост, юзер, пароль и имя базы в URL — ровно те, что заданы в `environment` compose-файла.

Ритуал начала работы над devio теперь: `docker compose up -d` → `fastapi dev app/main.py` → (в другом терминале) `npm run dev`.

## 8. Как не надо

- ❌ **`postgres:latest`** — версия должна быть зафиксирована; «поехавший» latest — классика сломанного окружения
- ❌ **База без volume** — работает до первого `down`, потом данные испаряются. Проверь, что `volumes` прописан
- ❌ **`docker compose down -v` на автомате** — флаг `-v` удаляет данные; набирай его только когда цель именно сброс
- ❌ **Хранить в контейнере что-то ценное вне тома** — контейнер по определению одноразовый
- ❌ **Ставить параллельно «системный» Postgres** — два постгреса будут драться за порт 5432; если системный уже стоит, останови его или поменяй левую часть проброса (`"5433:5432"` и порт в DATABASE_URL)
- ❌ **Коммитить будущие прод-секреты в compose** — локальные devio/devio можно, реальные пароли — нет

## Резюме

- Docker = изолированные, воспроизводимые, одноразовые окружения; для разработки devio — способ иметь Postgres без установки в систему
- Образ → шаблон, контейнер → запущенный экземпляр, том → выживающие данные
- `docker-compose.yml` — конфигурация контейнеров как код, в git
- Повседневность: `up -d` / `logs -f` / `down`; том хранит базу, контейнеры пересоздаются свободно
- FastAPI и Next живут на хосте как раньше; в Docker — только база, соединение через проброшенный порт
