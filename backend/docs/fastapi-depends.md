# FastAPI Depends: система зависимостей (подробный разбор)

Продолжение `fastapi-basics.md`. Формат тот же: каждый пример подписан файлом, к которому относится.

---

## 0. Куда что кладётся: структура

К прошлой структуре добавляются два файла:

```
backend/
├── app/
│   ├── __init__.py
│   ├── main.py
│   ├── schemas.py
│   ├── data.py
│   ├── db.py                 # ← НОВЫЙ: подключение к БД, get_db
│   ├── dependencies.py       # ← НОВЫЙ: общие зависимости (auth, пагинация, алиасы)
│   └── routers/
│       ├── __init__.py
│       ├── roadmaps.py
│       └── users.py
└── requirements.txt
```

Логика раскладки:
- `db.py` — всё про подключение к базе: engine, фабрика сессий, зависимость `get_db`
- `dependencies.py` — зависимости, которые нужны нескольким роутерам: `get_current_user`, пагинация, `Annotated`-алиасы
- Зависимость, нужная только одному роутеру, может жить прямо в его файле — выносить заранее не обязательно

## 1. Что такое зависимость

**Определение:** зависимость — это функция, которую FastAPI сам вызывает *перед* хендлером и результат которой подставляет в аргумент хендлера.

```python
# app/dependencies.py
def pagination(limit: int = 10, offset: int = 0) -> dict:
    return {"limit": limit, "offset": offset}
```

```python
# app/routers/roadmaps.py
from fastapi import APIRouter, Depends
from app.dependencies import pagination

router = APIRouter(prefix="/roadmaps", tags=["roadmaps"])

@router.get("/")
def list_roadmaps(pg: dict = Depends(pagination)):
    # pg == {"limit": 10, "offset": 0} или что пришло в query
    ...
```

Пошагово, что происходит на `GET /roadmaps?limit=5`:

1. FastAPI смотрит на сигнатуру хендлера и видит `pg: dict = Depends(pagination)`
2. Прежде чем вызывать хендлер, он вызывает `pagination`
3. **Ключевой момент:** сигнатура `pagination` анализируется по тем же правилам, что и сигнатура эндпоинта (см. `fastapi-basics.md`, раздел 6). `limit` и `offset` — примитивы, в пути их нет → это query-параметры. Со всей валидацией: `?limit=abc` даст 422, до твоего кода не дойдёт
4. Результат `{"limit": 5, "offset": 0}` кладётся в аргумент `pg`
5. Вызывается хендлер

**Что это даёт:** `pagination` — переиспользуемый фрагмент контракта. Подключишь её в 10 эндпоинтов — в каждом автоматически появятся оба query-параметра: в валидации, в `/docs`, с дефолтами. Изменишь дефолтный `limit` в одном месте — изменится везде.

**Аналогия с твоим стеком.** Ближайший родственник — middleware в Express, но с тремя важными отличиями:

| Express middleware | FastAPI Depends |
|---|---|
| вешается на путь/приложение | подключается точечно, в сигнатуре конкретного хендлера |
| передаёт данные мутацией `req.user = ...` (нетипизированно) | возвращает значение прямо в типизированный аргумент |
| про свои query-параметры фреймворк не знает | параметры зависимости — часть контракта, попадают в валидацию и доки |

## 2. Почему нельзя «просто вызвать функцию внутри хендлера»

Резонный вопрос: чем `Depends(pagination)` лучше вот этого?

```python
# ❌ так не надо
@router.get("/")
def list_roadmaps(limit: int = 10, offset: int = 0):
    pg = pagination(limit, offset)
    ...
```

Формально работает, но:

1. **Дублирование сигнатуры.** `limit` и `offset` пришлось объявить в самом хендлере и прокинуть руками. В десяти эндпоинтах — десять копий. Поменял параметры пагинации — правишь десять сигнатур.
2. **Для сложных зависимостей это вообще невозможно.** `get_current_user` нужен заголовок запроса и сессия БД — внутри обычного вызова функции их взять неоткуда, их выдаёт фреймворк.
3. **Теряются механизмы фреймворка:** кеширование на запрос (раздел 4), автоматический teardown (раздел 5), подмена в тестах (раздел 8).

Правильная ментальная модель: `Depends` — это способ сказать FastAPI *«вот этот кусок логики — часть обработки запроса, управляй им сам»*. Обычный вызов — это «моя внутренняя кухня, фреймворк не в курсе».

## 3. Цепочки зависимостей

Зависимость сама может объявлять зависимости — так же, через `Depends` в своей сигнатуре. FastAPI строит дерево и разрешает его целиком.

Вот как выглядит слоёная конструкция auth (сигнатуры реальные, тела — псевдокод, собирать будешь при реализации auth):

```python
# app/db.py
def get_db():
    ...  # yield-зависимость, полный разбор в разделе 5
```

```python
# app/dependencies.py
from fastapi import Depends, HTTPException
from fastapi.security import OAuth2PasswordBearer
from app.db import get_db

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="auth/login")

# УРОВЕНЬ 2: зависит от токена и БД
def get_current_user(
    token: str = Depends(oauth2_scheme),   # достаёт Authorization: Bearer ...
    db=Depends(get_db),                    # сессия БД
):
    # 1. jwt.decode(token) → невалиден/просрочен → raise HTTPException(401)
    # 2. взять user_id из payload
    # 3. найти юзера в db → нет → raise HTTPException(401)
    # 4. return user
    ...

# УРОВЕНЬ 3: зависит от уровня 2
def get_current_admin(user=Depends(get_current_user)):
    if user.role != "admin":
        raise HTTPException(status_code=403, detail="Admins only")
    return user
```

```python
# app/routers/roadmaps.py
from app.dependencies import get_current_admin

@router.delete("/{slug}")
def delete_roadmap(slug: str, admin=Depends(get_current_admin)):
    # сюда попадаем ТОЛЬКО если: токен валиден, юзер существует, роль admin
    ...
```

Что делает FastAPI на `DELETE /roadmaps/frontend`:

```
delete_roadmap
└── get_current_admin
    └── get_current_user
        ├── oauth2_scheme   → токен из заголовка (нет заголовка → 401)
        └── get_db          → сессия БД
```

Дерево разрешается от листьев к корню: сначала токен и сессия, потом юзер, потом проверка роли, и только потом хендлер. `raise HTTPException` на **любом** уровне немедленно прерывает запрос — хендлер не вызовется.

Два вывода:

- **Авторизация = зависимость.** «Только для админов» — это не `if` внутри хендлера, а `Depends(get_current_admin)` в сигнатуре. Появится роль модератора — напишешь `get_current_moderator`, хендлеры меняются на одно слово.
- Хендлер декларирует только верхний уровень потребности («мне нужен админ») и ничего не знает про токены и БД. Это и называется инверсией зависимостей.

## 4. Кеширование в рамках запроса

Посмотри на дерево выше: если хендлеру **тоже** нужна БД, `get_db` встретится в дереве дважды:

```python
# app/routers/users.py
@router.get("/me/progress")
def my_progress(
    user=Depends(get_current_user),   # внутри себя просит get_db
    db=Depends(get_db),               # и хендлер просит get_db
):
    ...
```

FastAPI вызовет `get_db` **один раз** и переиспользует результат во всех местах дерева. Правила:

- Кеш живёт в рамках одного запроса. Следующий запрос — всё заново
- Ключ кеша — сама функция: `Depends(get_db)` везде даст один объект
- Отключается через `Depends(get_db, use_cache=False)` — нужно редко, не трогай, пока не поймёшь зачем

Практическое следствие: **в одном запросе — одна сессия БД**, сколько бы зависимостей её ни просили. Это то поведение, которое ты бы и хотел: все операции запроса идут в одной сессии/транзакции.

## 5. Yield-зависимости: setup + teardown

Самый важный практический паттерн. Проблема: сессия БД должна быть **открыта до** хендлера и **гарантированно закрыта после** — даже если хендлер упал с ошибкой.

```python
# app/db.py
def get_db():
    db = SessionLocal()      # SETUP: создать сессию (SessionLocal появится при подключении БД)
    try:
        yield db             # ← значение уходит в хендлер, функция "замирает" здесь
    finally:
        db.close()           # TEARDOWN: выполнится после ответа. Всегда.
```

Как это работает:

1. `yield` внутри функции делает её **генератором** — функцией, которая умеет «выдать значение и поставить себя на паузу» (концептуально похоже на generator functions в JS: `function*` + `yield`)
2. FastAPI выполняет код до `yield`, забирает `db`, отдаёт его в хендлер
3. Хендлер отрабатывает, ответ уходит клиенту
4. FastAPI «будит» генератор — выполняется код после `yield`, то есть `finally: db.close()`
5. `finally` гарантирует закрытие и при исключении в хендлере — сессия не утечёт

Хронология одного запроса:

```
запрос → SessionLocal() → [хендлер работает с db] → ответ → db.close()
```

Правила yield-зависимостей:

- Ровно **один** `yield` на функцию
- Код после `yield` не может менять ответ — он уже отправлен
- Оборачивай `yield` в `try/finally`, если после него освобождается ресурс

Где ещё пригодится, кроме БД: временные файлы, блокировки, HTTP-клиент с закрытием соединения — любой ресурс с жизненным циклом «открыл — попользовался — закрыл».

## 6. Annotated: современный синтаксис

В свежей документации и туториалах зависимости записываются иначе. Это то же самое, но лучше:

```python
# старый стиль (везде выше — для простоты объяснения)
def handler(db: Session = Depends(get_db)): ...

# новый стиль
from typing import Annotated
def handler(db: Annotated[Session, Depends(get_db)]): ...
```

`Annotated[Тип, метаданные]` — стандартный механизм Python: «тип + прикреплённая к нему дополнительная информация». FastAPI читает метаданные и находит там `Depends`.

Чем новый стиль лучше:

1. **Честность синтаксиса.** `= Depends(get_db)` синтаксически выглядит как значение по умолчанию, но им не является — это инструкция фреймворку. `Annotated` убирает это враньё: тип и метаданные слева, дефолтов нет.
2. **Переиспользование.** `Annotated`-тип можно вынести в алиас:

```python
# app/dependencies.py
from typing import Annotated
from fastapi import Depends
from app.db import get_db

DbDep = Annotated[Session, Depends(get_db)]
CurrentUser = Annotated[User, Depends(get_current_user)]
AdminUser = Annotated[User, Depends(get_current_admin)]
```

```python
# app/routers/users.py — сигнатуры становятся короткими и единообразными
from app.dependencies import DbDep, CurrentUser

@router.get("/me")
def read_me(user: CurrentUser):
    return user

@router.get("/me/progress")
def my_progress(user: CurrentUser, db: DbDep):
    ...
```

TS-аналогия: это как вынести повторяющийся сложный тип в `type Alias = ...` — один раз определил, везде подключаешь.

Оба стиля полностью рабочие и взаимозаменяемые. Для нового кода бери `Annotated`; в чужом коде и старых туториалах будешь встречать оба.

## 7. Зависимости уровня роутера и приложения

Когда зависимость нужна **всем** эндпоинтам роутера, а её возвращаемое значение — нет (важен только side-effect: проверка, иначе исключение):

```python
# app/routers/admin.py
from fastapi import APIRouter, Depends
from app.dependencies import get_current_admin

router = APIRouter(
    prefix="/admin",
    tags=["admin"],
    dependencies=[Depends(get_current_admin)],   # список! выполняется для каждого роута
)

@router.get("/stats")
def stats():                  # в сигнатуре ничего про admin — но роут защищён
    ...
```

- `dependencies=[...]` принимает список — проверок может быть несколько
- Возвращаемые значения этих зависимостей выбрасываются
- Если в конкретном хендлере значение всё же нужно (сам объект админа) — объяви его в сигнатуре как обычно: благодаря кешу (раздел 4) зависимость не выполнится дважды

То же самое можно повесить на всё приложение: `FastAPI(dependencies=[...])` — например, глобальная проверка API-ключа.

Правило выбора: значение нужно в коде → зависимость в сигнатуре; нужна только проверка для группы роутов → `dependencies=` роутера.

## 8. Подмена зависимостей в тестах

Причина, по которой архитектура на `Depends` окупается стократно. У приложения есть словарь переопределений:

```python
# tests/test_roadmaps.py (понадобится при знакомстве с тестами — пока просто пойми принцип)
from fastapi.testclient import TestClient
from app.main import app
from app.db import get_db
from app.dependencies import get_current_user

def get_test_db():
    ...  # yield тестовой сессии (SQLite in-memory, например)

app.dependency_overrides[get_db] = get_test_db
app.dependency_overrides[get_current_user] = lambda: fake_user

client = TestClient(app)

def test_my_progress():
    resp = client.get("/users/me/progress")   # auth пройден фейковым юзером
    assert resp.status_code == 200
```

Механика: везде, где дерево зависимостей содержит `get_db`, FastAPI подставит `get_test_db`. **Код приложения не меняется вообще** — ни флагов `if TESTING`, ни моков импортов.

Это работает только потому, что хендлеры получают БД и юзера через `Depends`, а не импортируют глобальные объекты. Захардкодил глобальную сессию — тестировать можно только против реальной базы.

## 9. Как не надо

### Глобальная сессия БД

```python
# app/db.py
db = SessionLocal()          # ❌ создана при импорте модуля, живёт вечно

# app/routers/roadmaps.py
from app.db import db        # ❌ все запросы всех юзеров — в одной сессии

@router.get("/")
def list_roadmaps():
    return db.query(...)
```

Три проблемы: сессия не потокобезопасна (конкурентные запросы будут конфликтовать), никогда не закрывается (упавшая транзакция подвесит все последующие запросы), не подменяется в тестах. Всегда — `get_db` с `yield` из раздела 5.

### Тяжёлая инициализация внутри зависимости

Зависимость выполняется **на каждый запрос**. Создавать в ней engine БД, читать конфиг с диска, инициализировать что-то тяжёлое — значит делать это тысячи раз:

```python
def get_db():
    engine = create_engine(DATABASE_URL)   # ❌ engine и пул соединений — на КАЖДЫЙ запрос
    ...
```

Разделяй жизненные циклы: **долгоживущее** (engine, пул соединений, конфиг) создаётся один раз при старте приложения — на уровне модуля или в lifespan; **короткоживущее** (сессия из пула) — в зависимости. `SessionLocal()` в раздел 5 именно поэтому дёшев: он берёт готовое соединение из пула, а не открывает новое.

### Копипаста вместо зависимости

Маркер: одинаковый код в начале нескольких хендлеров.

```python
# ❌ в трёх хендлерах повторяется
payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
user = db.get(User, payload["sub"])
if user is None: raise HTTPException(401)
```

Это буквально определение `get_current_user`. Увидел повтор в начале хендлеров — выноси в зависимость.

### Логика ответа после yield

```python
def get_db():
    db = SessionLocal()
    yield db
    db.commit()        # ⚠️ спорно: commit после ответа — клиент получил 200 до записи
```

Код после `yield` выполняется, когда ответ уже ушёл. Пытаться там влиять на результат (коммитить, менять данные ответа) — источник тонких багов. После `yield` — только освобождение ресурсов.

## Резюме

- `Depends(fn)` = «вызови `fn` до хендлера, результат — в аргумент». Сигнатура `fn` анализируется как сигнатура эндпоинта
- Зависимости **компонуются**: auth — это цепочка токен → БД → юзер → роль
- **Кеш на запрос:** одна и та же зависимость в дереве выполняется один раз
- **`yield`** = setup до, teardown после; так подключается БД
- **`Annotated`** — современная запись; алиасы `DbDep`/`CurrentUser` держи в `dependencies.py`
- **`dependencies=`** роутера — защита группы роутов без значения
- **`dependency_overrides`** — подмена в тестах без изменения кода

Схема для devio: `app/db.py` (get_db) → `app/dependencies.py` (auth-цепочка + алиасы) → роутеры декларируют потребности в сигнатурах.

Следующий шаг — **база данных**: там `get_db` перестанет быть псевдокодом (появятся engine, `SessionLocal`, модели), и вся эта механика заработает вживую.
